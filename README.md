# 🚚 Перенос тюнинга грузовиков и прицепов между профилями ETS2/ATS

Десктопное приложение (Python 3.10+ / PyQt6) для переноса грузовиков и прицепов вместе со всеми
аксессуарами из одного сохранения **Euro Truck Simulator 2** / **American Truck Simulator**
в другое (например, между профилями).

> ⚠ **Обязательно закройте игру перед переносом и делайте резервные копии сохранений.**
> Программа сама создаёт резервную копию `game.sii.bak_ГГГГММДД_ЧЧММСС` перед каждой записью,
> но лишняя копия папки профиля не помешает.

## ❗ Честно об уровне проверки

* `SII_Decrypt.exe` — утилита для Windows. В среде разработки (Linux) её запустить нельзя, поэтому
  интеграция проверена **только на уровне вызова**: тест запускает подпроцесс-заглушку с той же
  командной строкой (`SII_Decrypt <вход> <выход>`), а также проверяются ошибки (нет утилиты,
  ненулевой код выхода, не запускается).
* Перенос проверен на **синтетических** сохранениях (`examples/`), повторяющих структуру настоящего
  `game.sii`, а **не на реальном сейве игры**. Перед использованием на основном профиле попробуйте
  на копии профиля.

## Установка и запуск

```bat
python -m pip install -r requirements.txt
python main.py
```

### Где взять SII_Decrypt.exe

Проект TheLazyTomcat: <https://github.com/TheLazyTomcat/SII_Decrypt> (раздел Releases).
Положите `SII_Decrypt.exe` рядом с `main.py` / собранным exe (или в подпапку `tools\`), либо укажите
путь в **⚙ Настройки** (путь сохраняется через QSettings). Кнопка «Проверить» проверяет наличие файла.

Можно обойтись без утилиты, если сохранения уже текстовые: в `config.cfg` игры установите
`uset g_save_format "2"` и пересохраните игру.

### Где лежат сохранения

* ETS2: `Документы\Euro Truck Simulator 2\profiles\<hex-ID профиля>\save\<номер или autosave>\game.sii`
* ATS: `Документы\American Truck Simulator\profiles\<hex-ID профиля>\save\<...>\game.sii`

(Если включена синхронизация Steam Cloud — папка `steam_profiles` вместо `profiles`.)

## Использование

1. **«Открыть исходное сохранение (Откуда копируем)»** — выберите `game.sii` (или перетащите файл на
   левую панель). Файл копируется во временную папку; при формате ScsC/BSII/3nK копия
   расшифровывается через SII_Decrypt в фоне, без окна консоли. Оригинал не изменяется.
2. Слева появится список грузовиков и прицепов (группы, поиск, фильтр «только транспорт игрока»,
   «Выбрать все / Снять выбор»): название (например «Scania S 2016», «SCS Box — фургон»), внутриигровой
   ID, номерной знак, количество аксессуаров.
3. **«Открыть целевое сохранение (Куда вставляем)»** — справа отображается сводка: игра,
   количество грузовиков/прицепов у игрока, свободные места в гаражах.
4. Отметьте транспорт и нажмите **«🚀 Перенести выбранное»**. После переноса показывается отчёт,
   журнал пишется внизу окна и в файл.

Журнал: `%LOCALAPPDATA%\SiiVehicleTransfer\logs\app.log` (Windows) или
`~/.sii_vehicle_transfer/logs/app.log`.

## Как работает перенос

1. **Парсер** находит блоки `тип : id { ... }` по балансировке фигурных скобок, пропуская строки
   в кавычках и комментарии (в номерах и надписях бывают `{` `}`). Блоки хранятся как смещения в
   исходном тексте, поэтому форматирование сохраняется байт-в-байт. Файл ~20 МБ разбирается
   примерно за секунду.
2. **Сбор зависимостей.** Для выбранного `vehicle` / `trailer` рекурсивно (обход в ширину, с защитой
   от циклов) собираются блоки, на которые указывают значения атрибутов: `accessories[i]`,
   вложенные ссылки внутри аксессуаров, `slave_trailer`, `trailer_definition` (блок `trailer_def`) и т.д.
   Копируются блоки типов `vehicle`, `trailer`, `trailer_def`, любые `vehicle_*` и любые `*_accessory`
   (`vehicle_accessory`, `vehicle_addon_accessory`, `vehicle_wheel_accessory`,
   `vehicle_paint_job_accessory`, `vehicle_sound_accessory`, `vehicle_drv_plate_accessory`,
   `trailer_accessory` ...).
3. **Новые ID** формата `_nameless.xxxx.xxxx.xxxx` (hex) уникальны относительно всех ID блоков и
   всех упоминаний `_nameless.*` в целевом файле, а также между собой.
4. **Замена ссылок.** Все ссылки на старые ID внутри копий заменяются новыми.
5. **Сброс «чужих» ссылок (→ `null`)**:
   * ссылки на блоки других типов — водитель (`driver_ai`, `driver_player`), гараж, задание
     (`job_offer_data`), игрок, экономика, журналы и т.п.;
   * ссылки `_nameless.*`, которых нет в исходном файле (висячие);
   * именованные ссылки (например, `garage.berlin`) сохраняются, только если такой блок того же
     типа есть в целевом файле.
   Список сброшенных полей выводится в отчёте. **Номерной знак (`license_plate`), пробег, износ,
   окраска и все остальные значения сохраняются.**
6. **Регистрация у игрока** (блок `player` целевого файла):
   * грузовики дописываются в `trucks: N` / `trucks[i]` (если у игрока вдруг массив называется
     `vehicles` — используется он); счётчик N обновляется, индексы продолжают нумерацию;
   * прицепы — в `trailers`. Прицеп, попавший в перенос как `slave_trailer` другого прицепа,
     копируется, но отдельно не регистрируется (как в игре);
   * параллельные массивы, длина которых должна совпадать: `truck_profit_logs` (для каждого
     грузовика создаётся пустой блок `profit_log` по образцу существующего),
     `trailer_utilization_logs` (пустой `trailer_utilization_log`), `trailer_defs` (дописываются
     скопированные `trailer_def`), `truck_placement` / `trailer_placement` — **только если это
     массивы** (тогда добавляется нейтральное `(0, 0, 0) (1; 0, 0, 0)`; в обычных сейвах это
     одиночные значения, их не трогаем). Если длины не совпадали ещё до переноса — предупреждение;
   * **активный грузовик не меняется**: `my_truck`, `assigned_truck`, `assigned_trailer`,
     `my_trailer*` остаются прежними.
7. **Гаражи** (опция, включена по умолчанию): каждый грузовик ставится в свободное место
   купленного гаража (`status` ≠ 0, где `vehicles[i]: null` и `drivers[i]: null`). Если мест нет —
   грузовик всё равно добавляется игроку, а в отчёте будет предупреждение.
8. **Сохранение**: новые блоки вставляются перед закрывающей `}` юнита `SiiNunit`, результат
   заново парсится и проверяется (все новые блоки на месте, счётчики совпадают, нет висячих ссылок).
   Затем создаётся резервная копия `game.sii.bak_ГГГГММДД_ЧЧММСС` и выполняется атомарная запись
   (временный файл + замена) в текстовом формате UTF-8 без BOM; стиль переводов строк (LF/CRLF)
   сохраняется. Игра читает текстовые сохранения без проблем. После записи файл перечитывается.
   Если зашифрованный исходник был целевым — после переноса он станет текстовым (это нормально).

## Ограничения

* Перенос **между ETS2 и ATS** разрешён, но выдаётся предупреждение: модели, детали и пути
  `/def/vehicle/...` у игр разные, игра может удалить такой транспорт.
* Проверить, существуют ли модели/детали (DLC, моды), невозможно — выдаётся предупреждение, если
  встречаются марки другой игры или неизвестные (вероятно, модовые) марки. Установите те же моды/DLC.
* Водители к перенесённым грузовикам не назначаются; назначьте их в игре.
* Структура сейва меняется с версиями игры. Программа обрабатывает её обобщённо, но на редких
  версиях возможны отличия — всегда проверяйте результат в игре и храните резервные копии.

## Сборка exe (PyInstaller)

```bat
build.bat
```

или вручную:

```bat
python -m pip install -r requirements-dev.txt
python -m PyInstaller --noconfirm --clean sii_vehicle_transfer.spec
```

Однофайловый вариант без spec:

```bat
python -m PyInstaller --noconfirm --onefile --windowed --name SiiVehicleTransfer main.py
```

Результат: `dist\SiiVehicleTransfer.exe`. Положите рядом `SII_Decrypt.exe`.

## Структура проекта

```
main.py                     точка входа (High-DPI, журнал, главное окно)
sii_transfer/               ядро без зависимостей от Qt
  errors.py                 исключения с русскими сообщениями
  models.py                 Block, SiiDocument, VehicleInfo, TransferReport ...
  parser.py                 структурный парсер SiiNunit
  analysis.py               зависимости, названия, определение игры, сводка
  idgen.py                  генерация уникальных ID
  decryptor.py              формат файла, поиск и запуск SII_Decrypt
  loader.py                 копия → расшифровка → парсинг → анализ
  transfer.py               перенос, регистрация у игрока, резервная копия, атомарная запись
  logging_setup.py          журнал в файл
ui/
  main_window.py            главное окно (панели, список, отчёт, журнал, drag&drop)
  settings_dialog.py        настройки (путь к SII_Decrypt, тема)
  styles.py                 QSS: тёмная/светлая тема
  workers.py                фоновые QThread: загрузка и перенос
examples/                   синтетические сохранения ETS2/ATS (+ generate_examples.py)
tests/                      pytest: ядро + smoke-тест GUI (offscreen)
```
